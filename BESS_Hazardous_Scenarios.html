Hazardous scenarios in a grid-connected BESS

Each scenario is written as in step 1 of the LOPA: one initiating event, the sequence it starts, what physically happens, and how a person gets hurt. Every initiating event now belongs to one component only, so PCS and BMS failures are separate scenarios.

How to read a scenario

Read each chain top to bottom, the same way as the overcharge example.

⚡ Initiating eventTechnical condition (what is failed) + mechanism (how it pushes the system toward harm). One component only.
▼ What happens nextThe propagation steps from the initiating event to the physical outcome.
💥 ConsequencesPhysical outcomes. There can be several; each becomes its own LOPA row.
🧍 HazardThe exact situation where a person is harmed: who, where and by what.
▶

PCS, BMS and the link between them

Your example says "PCS / BMS charging control fails". These are different failures with different independence problems, so they are split. If the PCS is the cause, a BMS-based trip can be credited; if the BMS is the cause, only a trip that does not use the BMS sensor, CPU or software can be credited.

Shared elements

How many safety functions rely on the same final element. If that element fails, all of them fail together, so they cannot be counted as separate layers.

The rack DC contactor carries most of the load. A welded contactor (scenario OC-03) defeats every function that relies on it. A diverse second final element, such as a DC breaker with shunt trip, gives a 1oo2 path to the safe state.

Measures without a sensor–logic–actuator path
